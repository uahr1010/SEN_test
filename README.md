## 1. 로컬에서 미리보기

> ⚠️ **`index.html`을 더블클릭해서 열면 내용이 안 나옵니다.**
> 브라우저 보안 정책상 `file://` 로 열린 페이지는 JSON 파일을 읽을 수 없습니다.
> 반드시 아래처럼 간단한 웹서버를 띄우고 `http://localhost:8000` 으로 접속하세요.

이 폴더에서 터미널(PowerShell)을 열고:

```bash
python -m http.server 8000
```

그다음 브라우저에서 `http://localhost:8000` 접속.
Node.js를 쓰신다면 이것도 됩니다:

```bash
npx serve .
```

## 2. GitHub 저장소 만들기

1. GitHub에서 새 저장소 생성 (예: `senkuzo-homepage`). **Public** 으로 만드세요.
   - Private으로 하려면 GitHub Pro/Team 이상이 필요합니다.
2. 이 폴더(`senkuzo-site`)의 **내용물**을 저장소 루트에 올립니다.
   `senkuzo-site` 폴더째 올리면 안 됩니다 — `index.html`이 저장소 최상단에 있어야 합니다.

터미널에서:

```bash
git init
```

```bash
git add . && git commit -m "홈페이지 초기 구성"
```

```bash
git branch -M main && git remote add origin https://github.com/사용자명/senkuzo-homepage.git && git push -u origin main
```

## 3. GitHub Pages로 배포

1. 저장소 → **Settings** → 왼쪽 메뉴 **Pages**
2. **Source**: `Deploy from a branch`
3. **Branch**: `main` / 폴더는 `/ (root)` → **Save**
4. 1~2분 뒤 `https://사용자명.github.io/senkuzo-homepage/` 에서 확인

### 도메인 연결 (senkuzo.com 등)

1. 저장소 루트에 `CNAME` 이라는 파일을 만들고 안에 도메인만 한 줄 적습니다:
   ```
   www.senkuzo.com
   ```
2. 도메인 등록 기관(가비아 등) DNS 설정에서:
   - `www` → CNAME → `사용자명.github.io`
   - 루트 도메인(`senkuzo.com`)도 쓰려면 A 레코드 4개:
     `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`
3. Settings → Pages → Custom domain에 도메인 입력 후 **Enforce HTTPS** 체크

## 4. Pages CMS 연결

1. https://app.pagescms.org 접속 → **Sign in with GitHub**
2. 권한 요청 시 위에서 만든 저장소를 선택해 접근 허용
3. 저장소 목록에서 `senkuzo-homepage` 선택
4. 루트의 `.pages.yml` 을 자동으로 읽어 **① 뉴스 / ② 뉴스 번역 / ③ 채용공고 / ④ 용어집** 4개 편집 메뉴 + **미디어** 쪽에 **① 프로젝트 데이터 / ② 이미지 / ③ 표지 사진**이 나타납니다

편집 후 **Save**를 누르면 Pages CMS가 GitHub에 커밋하고,
GitHub Pages가 자동으로 다시 배포합니다. **약 1분 뒤 사이트에 반영**됩니다.

### 다른 직원에게 편집 권한 주기

저장소 → Settings → Collaborators에서 GitHub 계정을 추가하면,
그 사람도 Pages CMS에 로그인해 편집할 수 있습니다.

## 5. 콘텐츠 수정 방법

Pages CMS 왼쪽 메뉴가 곧 편집 대상입니다.

| 메뉴 | 편집 내용 | 파일 |
|---|---|---|
| ① 뉴스 | 뉴스 추가·수정 (한국어만) | `content/news/<고유 ID>.json` (기사 하나당 파일 하나, GitHub Actions가 `content/news.json`으로 자동 컴파일) |
| ② 뉴스 번역 | ①의 영어·중국어·일본어 번역, 손으로 고칠 수 있음 | `content/news-i18n.json` |
| ③ 채용공고 | 채용공고 추가·수정 (한국어만) | `content/careers.json` |
| ④ 용어집 | 고유명사 표기 통일 (번역용) | `content/glossary/<고유 ID>.json` (용어 하나당 파일 하나, GitHub Actions가 `content/glossary.json`으로 자동 컴파일) |

새 번역을 자동으로 만드는 "번역 요청" 탭은 없앴습니다 — 저장소 **Actions** 탭 →
**"기사 번역"** → **Run workflow** 에서 `news_id` 칸에 ①의 "고유 ID"를 적고
손으로 돌리면 됩니다 (§5 "새 기사 등록" 참고).

**프로젝트(실적) 데이터**는 목록 폼이 아니라 **미디어 → 프로젝트 데이터**에
있습니다. 4,575건이라 폼으로 하나씩 펴서 편집하기엔 너무 많아서, 파일을
통째로 **내려받아 고친 뒤 같은 이름으로 다시 올려 덮어쓰는** 방식으로
바꿨습니다.

- 파일: `content/downloads/projects.json` (`{ "projects": [ {id, address, visible}, ... ] }`)
- **id**: 영문·숫자(예 `P4576`). 항목을 찾는 기준이라 중복되면 안 됩니다.
- **address**: 정확한 주소가 아니라 "서울특별시 강남구"처럼 **시/군/구 수준의
  공개 위치만** — 이 저장소는 public 이라 정확한 도로명·지번·건물명, 담당자
  이름, 계약금액 같은 내부 정보는 절대 넣으면 안 됩니다.
- **visible**: `false`로 두면 삭제하지 않고도 지도·지구본·집계에서 숨길 수
  있습니다.

**표지(첫 화면) 사진**도 목록 폼이 아니라 **미디어 → 표지 사진**에서
파일을 올리는 방식입니다.

- 파일 이름을 `main_1.png`, `main_2.png`, `main_3.png`, `main_4.png` 순서대로
  붙여서 올리세요(최대 4장). 확장자는 png/jpg/jpeg/webp 아무거나 됩니다.
- 사진을 바꾸려면 같은 이름으로 다시 올려 덮어쓰면 되고, 지우면 그 번호만
  빠지고 나머지 사진들로 이어집니다.
- 한 장도 올리지 않았다면 기본 사진 4장이 대신 나옵니다.
- 정적 사이트라 "이 폴더에 뭐가 있는지" 목록을 서버가 알려주지 못합니다 —
  그래서 `main_1`부터 순서대로 실제로 있는지 브라우저가 하나씩 직접
  확인해서 있는 것만 골라 씁니다. 번호를 건너뛰고 올려도(`main_1`,
  `main_3`만 있는 식) 있는 것들은 다 나오니 걱정 안 하셔도 됩니다.

회사소개·연혁·주요공법·CONTACT·히어로 문구·메뉴 이름 등 **나머지는 전부 고정값**입니다.
실수로 건드리기 쉬워 CMS에서 걷어냈습니다. 바꿔야 할 일이 생기면
`content/site.json` · `content/about.json` 을 직접 수정하세요.

### 다국어 입력

모든 텍스트 항목에 **한국어 / English / 中文 / 日本語** 4칸이 있습니다.
**한국어만 채워도 됩니다** — 번역이 비어 있으면 자동으로 한국어가 표시됩니다.
나중에 번역을 채우면 그때부터 해당 언어로 보입니다.

### 뉴스 추가하기

**① 뉴스** 메뉴를 열면 기사 목록이 표로 보입니다 — 25개씩 **쪽번호**로
넘겨 보고, 항상 **날짜 최신순**으로 정렬되어 있습니다. 기사 하나가 파일
하나(`content/news/<고유 ID>.json`)라서, 새로 만들기·수정·삭제가 서로
완전히 독립적입니다 — 한 기사를 고치거나 지워도 다른 기사는 절대 건드리지
않습니다.

목록 위 **"Add an entry"**(또는 **+**) 버튼으로 새 기사를 만듭니다.

- **고유 ID**: 영문·숫자·하이픈 (예: `news-2026-09-award`) — 중복만 안 되면 됩니다.
  이 값이 곧 파일 이름이 되므로, 저장한 뒤에는 바꾸지 마세요
- **날짜**: 이 날짜 기준으로 목록이 자동 정렬됩니다
- **분류**: 드롭다운에서 선택합니다(`언론보도` / `행사` / `홍보자료` / `논문` / `기술자료`).
  선택한 값이 그대로 홈페이지 **필터 버튼**이 됩니다
- **썸네일**: 업로드하면 `uploads/images/` 에 저장됩니다. 비워 두면 블루 그라디언트가 표시됩니다
- **원문 링크** (선택): 언론사 기사 등 외부 원문이 있을 때만 적습니다

저장하면 GitHub Actions(**뉴스 목록 컴파일**)가 `content/news/` 폴더 전체를
`content/news.json` 하나로 다시 합쳐 커밋합니다 — 실제 홈페이지는 이
합쳐진 파일을 읽습니다. **`content/news.json`은 직접 손대지 마세요** —
`content/news/` 폴더가 바뀔 때마다 자동으로 덮어써집니다.

카드를 누르면 항상 이 사이트 안의 상세 페이지(`news.html`)가 열립니다.
분류·날짜·요약(=본문 전체)·사진을 그 페이지에서 볼 수 있고, 원문 링크를 적었다면
"원문 보기" 버튼이 따로 뜹니다. 카드에서는 요약이 3줄까지만 보이고
나머지는 `...`으로 줄어듭니다 — 잘리지 않은 전체 글은 상세 페이지에 있습니다.
**별도의 "본문" 칸은 없습니다.** 카드 요약(`excerpt`)에 적은 내용이 곧 전체 글입니다.
짧게 쓰면 카드에도 상세 페이지에도 그 짧은 내용만 보이니, 전체 기사를 여기에 적으세요.

### 용어집 — 고유명사 표기 통일

회사명·공법명·기관명이 번역할 때마다 달라지지 않도록 정해 둔 표입니다.
현재 **59개** 등록되어 있습니다. 뉴스와 같은 방식으로, 용어 하나당 파일
하나(`content/glossary/<고유 ID>.json`)로 관리하고, GitHub Actions가
바뀔 때마다 번역 도구가 읽는 `content/glossary.json` 하나로 자동
컴파일합니다 — 그 컴파일된 파일은 직접 손대지 마세요.

**추가·수정은 Pages CMS → `④ 용어집`** 에서 합니다. 고유 ID(영문·숫자·
하이픈)와 네 칸(한/영/일/중)을 모두 채워 주세요 — 비우면 번역기가 그
말을 임의로 옮깁니다.

용어집도 예전엔 파일 하나(`content/glossary.json`)에 전부 들어 있어서,
아무 항목이나 하나 고쳐 저장해도 폼에 없는 값까지 통째로 다시 쓰이는
사고 위험이 있었습니다(뉴스에서 먼저 겪은 문제, §5 참고). 뉴스처럼
항목마다 파일을 나눠서 그 위험을 없앴습니다.

### 새 기사 등록 — 한국어로 먼저 올리고, 필요할 때만 번역 실행

뉴스는 **한국어 원문**(`content/news/<고유 ID>.json`)과 **번역**
(`content/news-i18n.json`)이 서로 다른 곳에 나뉘어 있습니다. 번역은 사람이
쓰는 게 아니라 GitHub Actions가 자동으로 채우는 값이라, `[① 뉴스]`(한국어
입력용)와 `[② 뉴스 번역]`(자동 생성 결과 확인·수정용)을 아예 다른 메뉴로
나눠 뒀습니다.

1. **`[① 뉴스]`**에 한국어로 기사를 씁니다. 여기서 끝 — 번역 없이도 바로 사이트에 실립니다.
   (다른 언어로 봐도 번역 전까지는 한국어 그대로 나옵니다. 오류가 아닙니다.)
2. 번역이 필요하면 **`[② 뉴스 번역]`** 페이지 위쪽의 **"번역 실행"** 버튼을 누르고,
   방금 만든 기사의 "고유 ID"를 입력한 뒤 확인합니다. Pages CMS 안에서
   바로 끝납니다 — 저장소 Actions 탭에 따로 갈 필요 없습니다.
3. GitHub Actions가 그 기사만 용어집을 참고해 번역해 `[② 뉴스 번역]`에
   넣고 자동 커밋합니다. 1~2분 걸립니다.

```text
[① 뉴스] 에 한국어로 기사 작성 → 저장 (여기까지만 해도 사이트에 실림)
        ↓  (선택) 번역이 필요하면
[② 뉴스 번역] → "번역 실행" 버튼 → 고유 ID 입력 후 확인
        ↓  용어집에서 이 기사에 쓰인 고유명사만 추려 프롬프트에 첨부
번역 API 호출 (영어 · 일본어 · 중국어)
        ↓
content/news-i18n.json 에 번역 추가 후 자동 커밋
        ↓
홈페이지 반영 ([② 뉴스 번역]에도 결과가 나타나 손으로 고칠 수 있음)
```

버튼이 안 보이거나 안 될 때의 대안: 저장소 **Actions** 탭 → **`기사 번역`** →
**Run workflow** → `news_id` 칸에 "고유 ID"를 적고 실행해도 결과는 같습니다.

#### API 키 등록 (최초 한 번)

키는 **GitHub Secrets** 에 넣습니다. 공개 저장소라도 외부에서 볼 수 없고,
Actions 로그에도 `***` 로 가려집니다. **코드나 홈페이지에는 절대 들어가지 않습니다.**

1. 저장소 → **Settings**
2. 왼쪽 **Secrets and variables** → **Actions**
3. **New repository secret**
   - Name: `OPENAI_API_KEY`
   - Secret: 발급받은 키
4. **Add secret**

쓸 모델은 같은 화면의 **Variables** 탭에서 지정합니다 (Secret 아님).

| 이름 | 값 | 필요 여부 |
|---|---|---|
| `SEN_TRANSLATE_MODEL` | 쓸 모델 이름 | 지정 안 하면 `gpt-4o` |
| `SEN_TRANSLATE_BASE_URL` | OpenAI 가 아닌 주소를 쓸 때만 | 대개 불필요 |

#### 잘 됐는지 확인

저장소 **Actions** 탭 → `기사 번역` 에서 실행 기록을 볼 수 있습니다.
번역이 끝나면 **용어집대로 안 나온 항목이 있는지 자동 검사**해서 경고를 남깁니다.
경고가 있으면 `[② 뉴스 번역]` 에서 해당 문장을 확인하세요.

#### 내 PC 에서 직접 돌려 보기 (선택)

```bash
pip install openai
```

```bash
setx OPENAI_API_KEY "sk-여기에-키"
```

```bash
python tools/translate_by_id.py --news-id news-2026-...-예시 --dry-run
```

`--dry-run` 은 결과만 보여 주고 `news-i18n.json` 을 건드리지 않습니다.
**키를 저장소 안 어떤 파일에도 적지 마세요.**

### 채용공고 추가 / "지원하기" 메일 주소 변경

③ 채용공고 →

- `지원 접수 이메일` : 전체 공고의 기본 접수 주소
- 각 공고의 `이 공고 전용 접수 메일` : 비워 두면 위 기본값 사용
- 메일 제목·본문 양식은 `content/site.json` 의 `careers.applyMailSubject`/`applyMailBody`
  고정값입니다 (`{job}` 자리에 공고명이 들어감). CMS 폼에는 없는 값이라 여기 두었습니다
  — ③ 채용공고 폼에 있었다간 저장할 때마다 지워집니다(아래 참고).
- `마감일`을 비우면 마감 배지가 표시되지 않습니다 (상시채용)

지원자가 "지원하기"를 누르면 먼저 **팝업**이 뜹니다 — 받는사람 이메일과 공고명을
한 번 보여주는 확인 창입니다. 팝업 안의 "메일 보내기"를 누르면 그때 지원자 본인의
메일 앱이 열리고, 받는사람·제목·본문 양식이 채워져 있습니다. 마지막 "보내기"는
지원자가 직접 눌러야 합니다.

> **왜 자동으로 전송되지 않나요?**
> 이 사이트는 서버가 없는 정적 사이트라, 버튼 클릭만으로 메일을 대신 발송하려면
> 발송 자격증명(SMTP 비밀번호·API 키)을 어딘가에 저장해 둬야 합니다. 이 저장소는
> public 이라 그 값이 그대로 공개돼 버립니다. `mailto:` 방식은 그런 자격증명이
> 전혀 필요 없는 대신, 지원자가 마지막 "보내기"를 직접 눌러야 합니다.
> 정말로 자동 전송이 필요하면 Formspree 같은 외부 폼 서비스를 붙이는 방법이
> 있습니다 (§8 "다음 단계" 참고) — 다만 그 메일함 소유자가 해당 서비스에서
> 한 번 이메일 인증을 해야 합니다.

⚠️ `content/careers.json` 에는 **지원 접수 이메일·채용공고**만 있습니다.
"채용" 섹션 제목·문구·마감 라벨 같은 나머지는 `content/site.json` 의
`careers` 쪽에 있습니다 — 예전엔 같은 파일에 같이 있었는데, ③ 채용공고
폼을 저장할 때마다 그 폼에 없는 값(제목·문구 등)까지 통째로 지워지는
사고가 있어서(뉴스에서 겪은 것과 같은 문제, 2026-08-13) CMS가 손대지
않는 파일로 옮겼습니다.

### 프로젝트 실적 — 국내는 실제 지도, 국외는 지구본

프로젝트 섹션은 카드 목록이 아니라 **국내/국외 탭 + 지도/지구본**입니다.
왼쪽 통계(누적 실적·수행 지역·지역별 순위)는 `content/downloads/projects.json`
을 집계한 값으로 국내/국외 공통이고, 오른쪽 시각화만 탭마다 다릅니다.

**국내 탭**은 2026-08-14부터 실제 지도(MapLibre, CARTO 무료 타일)입니다.
`assets/data/project_points.json`(현장 4,576곳의 좌표)을 지도 레이어로
전부 올려 두고, 확대할수록 뭉친 덩어리가 저절로 갈라집니다 — 예전의
"시/도 클릭 → 시/군/구 팝업" 방식은 없앴습니다. 배율에 따라 시/도
색칠(멀리서) → 시/군/구 원 → 개별 현장 점(가까이서) 순으로 바뀝니다.

⚠️ **이 지도는 번지·도로명 단위의 정밀 주소를 보여줍니다**
(`content/downloads/projects.json`은 시/군/구까지만 — 서로 다른 공개
범위입니다). 4,576건 중 3,405건이 이 정도로 구체적이며, 이 공개 범위
확대는 **2026-08-14 사내 확인을 받은 사안**입니다. 주소를 다시 바꾸거나
좌표를 재생성할 때는 이 점을 다시 확인하세요 — 카카오 로컬 API로 좌표를
바꾸는 스크립트는 `_지도_테스트/tools/geocode_kakao.py`에 있습니다.

**국외 탭**(지구본)은 그대로입니다 — 가만히 두면 한국이 정면을 보는
자세로 멈춰 있고, 마우스로 끌면 돌아가다 손을 떼면 다시 그 자세로
스르륵 돌아옵니다. 저절로 계속 도는 자동 자전은 없습니다.

국내 지도가 쓰는 데이터: `assets/data/kgeo.json`(시/도 17개 경계) ·
`assets/data/munis.json`(시/군/구 249개 경계) · `assets/data/kmap.json`
(전체명↔축약명 매핑) · `assets/data/project_points.json`(현장 좌표,
★ 이것만 시/군/구 단위가 아니라 번지 단위) · `assets/fonts/Noto Sans Bold/
0-255.pbf`(지도 위 숫자 글자 — 폴더 이름의 띄어쓰기를 반드시 그대로
유지해야 합니다. 안 그러면 MapLibre가 그 타일의 원까지 통째로 버립니다).

```json
{ "id": "P4576", "address": "서울특별시 강남구", "visible": true }
```

- **고유 ID**: 수정·삭제할 때 이 ID로 항목을 찾습니다. 겹치면 안 됩니다.
- **공개 위치**: 아래 참고
- **visible**: `false` 로 두면 지우지 않고도 지구본·집계에서 숨길 수 있습니다

프로젝트 수는 별도로 저장하지 않고, 배열 항목 수를 그대로 셉니다.
지역별 건수도 저장해 두지 않고, 사이트가 매번 다시 집계합니다 —
그래야 숫자가 실제 데이터와 어긋날 일이 없습니다.

#### ⚠️ 정확한 주소를 적지 마세요 — 이 저장소는 public 입니다

이 저장소는 누구나 코드를 볼 수 있는 **공개(public) GitHub 저장소**입니다.
`content/downloads/projects.json` 에 적은 내용도 예외가 아닙니다.

| | 예시 |
|---|---|
| **적어도 되는 것** | `서울특별시 강남구`, `경기도 성남시`, `부산광역시 해운대구` |
| **적으면 안 되는 것** | 정확한 도로명·지번·건물명, 담당자 이름·연락처, 계약금액, 고객사 내부정보 |

정확한 주소가 필요한 내부 업무는 회사 내부 시스템에서 따로 관리하고,
홈페이지에는 **공개해도 되는 수준으로 사람이 걸러낸 위치만** 옮겨 적으세요.

**한 번이라도 커밋한 정확한 정보는 나중에 지워도 Git 이력에 남습니다.**
"일단 정확히 적고 나중에 지우면 되지"는 통하지 않습니다 — 처음부터 공개 가능한
수준으로만 적어야 합니다.

#### 위치는 어떻게 적어야 하나

`시/도 + 시/군/구` 가 들어가면 가장 정확합니다.

| 적은 위치 | 결과 |
|---|---|
| `서울특별시 강남구` | 강남구 정확한 위치 |
| `강북구` | 시도가 없어도 구 이름으로 찾아냄 |
| `충청남도 예산군` | 예산군 위치 |
| `충청남도` | 충남 중심에 표시 (대략 위치) |
| `국립중앙박물관` | **찍히지 않음** — 건물명은 행정구역이 아닙니다 |

좌표 사전은 `assets/data/geo.json` 에 있습니다 (시군구 200여 곳 + 시도 중심 + 해외).
새 지역이 자꾸 "시도 중심"으로만 잡히면 이 파일에 항목을 추가하면 됩니다.

## 6. 디자인 수정 방법

### 색상 바꾸기

`assets/css/base.css` 맨 위 `:root` 블록만 고치면 사이트 전체에 반영됩니다.

```css
--c-navy:      #0A2540;   /* 가장 진한 남색 — 다크 섹션 배경 */
--c-blue:      #0B5FCE;   /* 메인 블루 — 버튼·링크·강조 */
--c-blue-dark: #084BA3;   /* 버튼 hover */
--c-blue-soft: #7FB2F0;   /* 밝은 포인트 */
--c-tint:      #EFF5FD;   /* 아주 연한 블루 배경 */
```

### 폰트 바꾸기

같은 파일의 `--font-sans`(본문), `--font-display`(숫자·연대·인용구 등 강조).
현재는 **본문·강조 모두 Noto Sans KR**(구글 폰트) 하나로 통일되어 있습니다
(`--font-display: var(--font-sans)`). 강조에만 다른 폰트를 쓰고 싶으면 그 한 줄만 바꾸면 됩니다.
웹폰트가 필요 없으면 `index.html` 상단 웹폰트 블록을 통째로 지우세요 (시스템 폰트로 대체).

### 로고 바꾸기

`assets/img/logo.png` 파일 자체를 새 로고 이미지로 덮어쓰면 끝입니다.
이 파일은 세 군데에서 함께 쓰입니다 — 마크업을 따로 고칠 필요는 없지만,
**원본 비율(가로:세로)이 지금과 많이 다르면** 아래 `<img>` 태그의
`width`/`height` 속성도 새 파일 크기에 맞게 고쳐 주세요 (레이아웃이 깨지지 않도록
브라우저가 미리 자리를 잡는 값이라, 실제 표시 크기는 CSS `height: clamp(...)` 가 따로 정합니다).

| 위치 | 파일 |
|---|---|
| 헤더 로고 | `index.html`, `news.html`, `news-list.html` 의 `.topbar__logo` 안 `<img>` |
| 푸터 로고 | `index.html`, `news.html`, `news-list.html` 의 `.site-footer__brand` 안 `<img>` |

표시 크기를 바꾸려면 `assets/css/atlas.css` 의 `.topbar__logo img`(헤더) ·
`.site-footer__brand img`(푸터) 의 `height` 값을 고치세요.

파비콘은 `assets/img/favicon.png` 를 교체하면 됩니다 (`index.html`, `news.html` 양쪽의
`<link rel="icon">` 가 이 파일을 가리킵니다). 정사각형에 가까운 단순한 그림일수록
작은 크기(16×16)에서도 잘 보입니다.

### 섹션 순서 바꾸기 / 추가

`index.html` 의 `<section class="scene" id="scene-...">` 블록 순서를 바꾸면 됩니다.
오른쪽 진행 점(`#prog`)은 `atlas.js`가 `.scene` 개수를 보고 그때그때 자동으로
만드므로, 번호를 따로 맞춰 줄 필요는 없습니다. 맨 위의 표지(`.cover`)는
`.scene`이 아니라서 이 점 목록에 포함되지 않습니다.

## 7. 자주 겪는 문제

**Q. 화면에 빨간 오류 박스가 뜨고 내용이 안 보여요**
→ `index.html`을 더블클릭해서 열었을 때 발생합니다. [1번 항목](#1-로컬에서-미리보기)대로 웹서버를 띄우세요.

**Q. CMS에서 저장했는데 사이트가 그대로예요**
→ ① 배포에 1~2분 걸립니다. ② 저장소 → Actions 탭에서 배포 성공 여부를 확인하세요.
③ 브라우저 캐시일 수 있으니 `Ctrl+Shift+R` 로 강력 새로고침.

**Q. 이미지가 안 보여요**
→ 반드시 Pages CMS의 업로드 기능을 쓰세요. 직접 경로를 적을 때는
`/uploads/images/파일명.jpg` 형식이어야 합니다.

**Q. 특정 언어로만 글자가 안 나와요**
→ 정상입니다. 해당 언어 칸이 비어 있으면 한국어로 대체 표시됩니다.

**Q. 화면 전체가 뿌옇게 덮여 있고 아무것도 클릭되지 않아요**
→ **프로젝트 모달이 항상 떠 있어서** 생기는 문제였습니다. 2026-08-11에 수정했습니다.

`index.html` 의 모달은 `<div class="modal" hidden>` 으로 숨겨 두는데,
`components.css` 의 `.modal { display: grid }` 가 브라우저 기본 규칙
`[hidden] { display: none }` 을 이겨서 `hidden` 이 무시되고 있었습니다.
그 결과 모달의 배경막(남색 62% 반투명 + `blur(4px)`)이 페이지 전체를 덮어
뿌옇게 보이고, 클릭도 전부 그 막에 막혔습니다.

`base.css` 리셋에 아래 한 줄을 넣어 해결했습니다. **지우지 마세요.**

```css
[hidden] { display: none !important; }
```

> 앞으로 `display` 를 지정한 요소를 `hidden` 으로 여닫을 때도 이 규칙이 지켜 줍니다.

**Q. 글자가 뿌옇고 흐릿하게 보여요 (특히 Windows)**
→ 원인이 두 가지였고 2026-08-11에 모두 수정했습니다.

1. `base.css` 의 `-webkit-font-smoothing: antialiased` — macOS 전용 보정값입니다.
   Windows 에서는 이게 ClearType(서브픽셀 렌더링)을 꺼 버려 글자가 얇고 뿌옇게 보입니다.
   **이 속성을 다시 넣지 마세요.**
2. 본문 폰트가 `--font-sans` 에 적혀만 있고 불러오지는 않아,
   대부분의 Windows PC 에서 '맑은 고딕'으로 떨어지고 있었습니다.
   `index.html` 에서 웹폰트를 직접 불러오도록 고쳤습니다.
   (2026-08-12 에 본문 폰트를 Pretendard → **Noto Sans KR** 로 교체했습니다)

함께 손본 것 — 남색 배경 위 흰 글자의 투명도를 올려 대비를 높였습니다
(예: 히어로 소제목 82% → 93%, 지표 라벨 68% → 85%, 히어로 격자 무늬 16% → 10%).

**Q. 페이지 전체가 반투명하게 굳어 보여요**
→ 스크롤 등장 애니메이션이 중간에 멈춘 상태입니다. 2026-08-11에 수정했습니다.
그래도 재현되면 `Ctrl+Shift+R` 로 강력 새로고침해 주세요 (브라우저가 예전 CSS/JS를 캐시하고 있을 수 있습니다).
구조상 이제 **애니메이션이 실패해도 내용은 항상 또렷하게** 보입니다 —
`index.html` 상단 인라인 스크립트가 `<html>` 에 `js-anim` 을 붙였을 때만 숨김이 적용되고,
`assets/css/components.css` 의 `.js-anim .reveal` 규칙이 그 플래그에 걸려 있습니다.
**`.reveal { opacity: 0 }` 처럼 플래그를 떼면 증상이 재발하니 주의하세요.**

**Q. 메뉴를 눌렀는데 제목이 헤더에 가려져요**
→ `assets/css/base.css` 의 `--header-h` 값(현재 76px)이 실제 헤더 높이와 맞는지 확인하세요.

현재는 본문을 JavaScript로 그리기 때문에 네이버·다음 검색 노출이 약합니다.

### 문의 폼 / 지원하기 자동 전송

현재 CONTACT와 채용 "지원하기"는 둘 다 `mailto:` 링크 방식입니다(서버 불필요,
발송 자격증명 불필요, 대신 지원자·문의자가 마지막 "보내기"를 직접 눌러야 함).

버튼 클릭만으로 조용히 메일이 도착하게 하려면 [Formspree](https://formspree.io) 같은
외부 폼 서비스를 붙이면 정적 사이트 그대로 폼 제출을 받을 수 있습니다. 대략적인 흐름:

1. Formspree 에서 새 폼을 만들고, 받을 이메일 주소를 등록

## 기술 메모

- 빌드 도구·프레임워크 없음. 순수 HTML/CSS/JS (ES5 문법 + IntersectionObserver)
- 외부 의존성 (모두 CDN)
  - Google Fonts — Noto Sans KR (본문·강조 공용, 100~900 가변)
  - three.js 0.155 — 실적 지구본(프로젝트 섹션에서만 불러옴). UMD 빌드가 r160부터 제거 예정이라 버전 고정
  - MapLibre GL JS 4.7.1 — 국내 실적 지도(프로젝트 섹션에서만 불러옴). 배경 타일은
    CARTO 무료 라스터 타일. 둘 다 API 키·결제수단 필요 없음
- 지구본은 화면에 보일 때만 렌더링합니다 (IntersectionObserver + rAF)
- WebGL을 못 쓰면 지구본만 접히고 실적 숫자·지역 순위는 그대로 남습니다
- 국내 지도(MapLibre)는 `assets/data/project_points.json`(현장 4,576곳의
  번지 단위 좌표)을 지도 레이어로 올립니다. 글자 파일(`assets/fonts/
  Noto Sans Bold/0-255.pbf`)이 없으면 원 위의 숫자뿐 아니라 그 타일의
  원 자체가 통째로 안 그려집니다 — MapLibre가 글자를 못 받은 타일을
  버리기 때문입니다
- 지원 브라우저: Chrome / Edge / Safari / Firefox 최신 2개 버전, iOS·Android
- 접근성: 키보드 네비게이션, `aria-expanded`, `prefers-reduced-motion` 대응
